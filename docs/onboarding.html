Core End-to-End Flows

Every write is an HTTP call via a Solid 'use server' function (never WebSocket RPC). Realtime channels strictly push viewer-projected updates after commit.

Step 1 · Client Optimistic Action Controller runs a Solid 2.0 action(function*), updating createOptimisticStore immediately while gating permissions.
Step 2 · HTTP Single Command Seam Posts a discriminated union to dispatchBoardCommand or changePokerRoom over /_server with signed cookies attached.
Step 3 · Server Validate & Transact Valibot parses input, rate limiter checks burst quota, and SqlBoardOperations / PokerRoomStorage runs one atomic SQLite transaction.
Step 4 · Fan-Out Per-Viewer Projection Actor gets a viewer-projected HTTP response; other sockets receive individually redacted WS/SSE frames with monotonic version.

Zero accounts, zero PII (ADR-0001). Identity is an opaque capability in a signed HttpOnly cookie (retrocks_session), supporting key rotation via comma-separated SESSION_SECRET.

Step 1 · First GET Async SSR Cookie Mint Middleware sets event.renderMode = 'async' on /b/:id & /p/:id so the server mints participantId before headers flush.
Step 2 · Isolation Per-Board Salted Hash participantId is hashed with each Board's token_salt (SHA-256). Same browser gets unlinkable hashes across Boards.
Step 3 · Fragment Zero-Leak Link Claim Co-Facilitator Link puts #f=<43-char-token> in the URL fragment (never sent to HTTP logs or Referer). Client exchanges it via server action.
Step 4 · Upgrade Scrub & Reconnect Server verifies salted hash, upgrades HttpOnly cookie (max 35 Boards), client scrubs hash with history.replaceState, stream reconnects.

Switch between Cloudflare Workers and Node with one env flag (RETROCKS_RUNTIME=node) — zero changes to routes, components, or SQL logic (ADR-0002).

Data Model (7 SQLite Tables)

  • boards — metadata, encrypted/hashed facilitator token, is_blurred, blind_voting, is_locked, timer fields, monotonic version.
  • columns — ordered categories (accent, is_action_column).
  • card_groups & cards — anonymous notes, optional group merge, Action Item flags (is_action_item, action_done, action_owner).
  • votes, reactions, comments — keyed by salted voter/author hashes; child tables carry board_id so SQL runs verbatim on DO & Node SQLite.

Key Domain Invariants

  • Private Mode — server redacts all non-authored cards (even for Facilitators) into placeholder line counts until revealed.
  • Blind Voting — viewer sees their own cast counts while aggregate totals stay hidden server-side until reveal.
  • Locked State — freezes content mutations while keeping search, export (/api/boards/:id/export), print, and Facilitator Action Item updates open.
  • Workspace Context — BoardWorkspaceContext exposes reactive getters to Column/Group/Card panels to prevent prop drilling.

Session & Voting Engine

  • Display Names (ADR-0003) — Room-specific exception to Board anonymity; Participants pick a session-local Display Name via joinPokerRoom formAction.
  • Story Queue & Decks — reorderable Stories, preset/custom Decks (poker-deck-policy.ts), and discard prompts (poker-discard-policy.ts) when mid-round edits wipe votes.
  • Single-Flight Mutations — changePokerRoom returns typed PokerResult with HTTP status mapping (409 on ROUND_CHANGED, STORY_LOCKED, ROOM_CLOSED).

Close & Reopen Lifecycle (ADR-0004)

  • Closing a Room — wipes the Participant roster and Co-Facilitator Link so Display Names never linger on closed summaries; retains only Facilitator session hashes.
  • Reopening a Room — turns saved hashes into pending Facilitator claims, routes returning users through the Display Name join screen, and marks all pre-close Stories as Locked Stories.
  • No-Store Headers — middleware forces Cache-Control: no-store on /p/* and /api/poker/*.

Solid 2.0 & Repo Guardrails (Day-1 Gotchas)

From AGENTS.md & docs/live-synchronization-effects.md
Props & Signals
Avoid function C({ name }) or passing accessors <C value={count} />
Do This Read props.name in JSX/memos; pass values <C value={count()} />
Effects Policy
Avoid Single-arg createEffect(fn) or effects for derived state / events
Do This Prefer createMemo, JSX bindings, ref, onSettled. Only use createEffect(compute, apply) when unavoidable (9 audited live-sync effects)
Stores & Async
Avoid 1.x solid-js/store, produce, <Suspense>, <ErrorBoundary>, onMount
Do This Draft writes setStore(s => { s.x = 1 }), <Loading>, <Errored>, onSettled, flush() before test assertions
Boundaries & CSS
Avoid Importing server code in client, touching .env, or ad-hoc vanilla CSS
Do This Mark server files import 'server-only', use virtual:solid-env/*, Tailwind v4 utilities first, and @ui-sdk/solid primitives

Day-1 Quickstart & Verification Commands

Local dev runs at http://127.0.0.1:3002
1. First-time setup 
pnpm install && cp .env.example .env
Set SESSION_SECRET in .env (32+ chars via openssl rand -base64 32).
2. Run dev server 
pnpm dev        # CF workerd + DO
pnpm dev:node   # Node + SSE
Default matches Cloudflare prod; use dev:node for SSE/SQLite fallback.
3. Run test suites 
pnpm test       # jsdom + node
pnpm test:watch # watch mode
Server tests run against in-memory node:sqlite with zero Wrangler mocks.
4. Pre-PR quality checks 
pnpm typecheck && pnpm lint && pnpm knip
TypeScript 7 check, oxlint, and dead-code check. Husky runs lint-staged on commit.
