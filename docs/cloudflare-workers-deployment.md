# Deploying Retrocks to Cloudflare Workers

Retrocks is configured to run natively on **Cloudflare Workers** (`workerd`) using `@cloudflare/vite-plugin`, SQLite-backed Durable Objects, Workers Static Assets, and the Workers Rate Limiting API.

## Architecture Overview

| Component | Configuration | Purpose |
| --- | --- | --- |
| **Worker Entry** | `src/worker.ts` (`main` in `wrangler.jsonc`) | Wraps Solid's `virtual:solid-ssr-handler`, binds `env` via `AsyncLocalStorage`, and intercepts WebSocket upgrades for `/api/boards/:id/live` and `/api/poker/:id/live`. |
| **Static Assets** | `dist/client` (`ASSETS` binding) | Serves hashed client bundles and public assets at the edge. |
| **Durable Objects** | `BOARD_ROOM` (`BoardRoom`), `POINTING_POKER_ROOM` (`PointingPokerRoom`) | SQLite-backed Durable Objects (`migrations` `v1` and `v2`) storing board/poker state and managing live WebSocket rooms. |
| **Rate Limiter** | `BOARD_CREATE_LIMITER` (`namespace_id: "1001"`) | Limits board/poker creation to 10 requests per 60 seconds per hashed client IP. |
| **Node Compatibility** | `compatibility_flags: ["nodejs_compat"]`, `compatibility_date: "2026-08-11"` | Provides `node:async_hooks` for per-request context and exposes Worker secrets/vars via `process.env`. |

## Prerequisites

- **Node.js** and **pnpm** installed locally.
- A **Cloudflare account** with Workers enabled.
- **Wrangler** (already included in `devDependencies` — invoke via `pnpm exec wrangler`).

## Environment Variables & Secrets

All environment variables are declared and validated in `env.ts`:

| Variable | Scope | Required | Notes |
| --- | --- | --- | --- |
| `SESSION_SECRET` | Server (runtime) | **Yes** | Minimum 32 characters. Signs session cookies (HMAC-SHA256). Supports comma-separated rotation (`"new,old"`). Read from `process.env` at boot; never baked into build artifacts. |
| `VITE_APP_NAME` | Client (build-time) | No | Defaults to `Retrocks`. Baked into the client bundle during `pnpm build` — changing it requires a rebuild. |
| `RETROCKS_RUNTIME` | Server (Node only) | No | Leave unset for Cloudflare Workers (defaults to Cloudflare). Only set to `node` for standalone Node builds. |
| `DATABASE_URL` | Server (Node only) | No | Unused on Cloudflare Workers (state lives in SQLite Durable Objects). |

Generate a strong `SESSION_SECRET`:

```bash
openssl rand -base64 32
```

## Local Verification (workerd)

Before deploying, verify the production build locally against `workerd`:

1. Create a `.dev.vars` file at the repo root (git-ignored) with your local secret:

   ```ini
   SESSION_SECRET=replace-with-32-plus-char-random-secret
   ```

2. Run the development server in `workerd`:

   ```bash
   pnpm dev
   ```

3. Build and preview the production bundle in `workerd`:

   ```bash
   pnpm build
   pnpm exec wrangler dev
   ```

## First-Time Deployment

1. **Authenticate Wrangler** with your Cloudflare account:

   ```bash
   pnpm exec wrangler login
   ```

2. **Set the production `SESSION_SECRET`** as a Worker secret:

   ```bash
   pnpm exec wrangler secret put SESSION_SECRET
   ```

   Paste the value generated by `openssl rand -base64 32` when prompted.

3. **Build and deploy to Cloudflare Workers**:

   ```bash
   pnpm deploy
   ```

   This builds the client and Worker bundles and regenerates `dist/server/wrangler.json` before Wrangler runs. Use this command after a standalone Node build too, since both builds write to `dist`.

   To customize the app name, set `VITE_APP_NAME` on the deploy command:

   ```bash
   VITE_APP_NAME="My Retrocks" pnpm deploy
   ```

   On the first deploy, Wrangler automatically applies the SQLite Durable Object migrations (`v1` for `BoardRoom`, `v2` for `PointingPokerRoom`) defined in `wrangler.jsonc`.

## Custom Domains

To serve Retrocks from your own domain instead of `*.workers.dev`:

1. Ensure the domain is active on your Cloudflare account.
2. Either add a **Custom Domain** in the Cloudflare Dashboard (**Workers & Pages → retrocks → Settings → Domains & Routes**), or add a `routes` block to `wrangler.jsonc`:

   ```jsonc
   {
     "routes": [
       { "pattern": "retro.example.com", "custom_domain": true }
     ]
   }
   ```

3. Re-run `pnpm deploy`.

## CI/CD (GitHub Actions)

To deploy automatically on pushes to `main`:

1. Create a Cloudflare API Token with **Edit Cloudflare Workers** permissions.
2. Add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as GitHub repository secrets.
3. Add a workflow file (e.g., `.github/workflows/deploy.yml`):

   ```yaml
   name: Deploy to Cloudflare Workers

   on:
     push:
       branches: [main]

   jobs:
     deploy:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: pnpm/action-setup@v4
         - uses: actions/setup-node@v4
           with:
             node-version: 22
             cache: pnpm

         - run: pnpm install --frozen-lockfile
         - run: pnpm typecheck
         - run: pnpm lint
         - run: pnpm test

         - name: Deploy Worker
           run: pnpm deploy
           env:
             CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
             CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
   ```

> **Note:** `SESSION_SECRET` is managed via `wrangler secret put` (or the Cloudflare Dashboard) and persists across deployments — it does not need to be re-uploaded on every CI run.

## Operations & Maintenance

### Rotating `SESSION_SECRET` (Zero Downtime)

`src/server/session.ts` signs cookies with the first secret in a comma-separated list and verifies against all listed secrets:

1. Generate a new secret (`openssl rand -base64 32`).
2. Update the Worker secret with `"<new_secret>,<old_secret>"`:

   ```bash
   pnpm exec wrangler secret put SESSION_SECRET
   ```

3. After existing sessions have expired (e.g., 1 week), update `SESSION_SECRET` again with only `"<new_secret>"`.

No rebuild is required because `SESSION_SECRET` is read at runtime.

### Live Logs

Stream real-time logs and exceptions from the deployed Worker:

```bash
pnpm exec wrangler tail
```

### Rollbacks

List recent deployments and roll back to a previous version if needed:

```bash
pnpm exec wrangler deployments list
pnpm exec wrangler rollback
```

## Troubleshooting

- **Worker fails at boot with `SESSION_SECRET` validation error**: Confirm the secret is set (`pnpm exec wrangler secret list`) and is at least 32 characters long.
- **`VITE_APP_NAME` change did not take effect**: Client `VITE_*` variables are baked into the bundle at build time, not read from Worker runtime vars. Re-run `pnpm build` with the new value and redeploy.
- **WebSocket connections failing behind a proxy**: Ensure your DNS/proxy forwards `Upgrade: websocket` headers to `/api/boards/:id/live` and `/api/poker/:id/live`. Cloudflare Custom Domains handle this automatically.
- **Local dev hitting Node runtime instead of Cloudflare**: Make sure `RETROCKS_RUNTIME` is not set to `node` in your shell environment when running `pnpm dev` or `pnpm build`.
