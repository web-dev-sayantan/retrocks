# Replacing effects safely in Solid 2.0

Retrocks declares `^2.0.0` for both `solid-js` and `@solidjs/web`. The lockfile and installed packages resolve both to **2.0.0**. The guidance below uses the official 2.0 docs and the cheatsheet bundled with the installed core package. [Manifest](../package.json) · [Lockfile](../pnpm-lock.yaml) · [Installed cheatsheet](../node_modules/solid-js/CHEATSHEET.md) · [Solid 2.0 migration guide](https://docs.solidjs.com/migration/from-solid-1)

## Derive values in the reactive graph

- Bind reactive values directly in JSX for text, classes, styles, and attributes. Use a function for cheap derived values and call it in JSX or another tracking scope. Use `createMemo` for shared or expensive work, or to suppress downstream updates when the result compares equal. Read props in the tracked expression. A read in the component body captures the value at setup. An effect that copies its compute result into a signal adds a reactive pass and can expose stale intermediate values. [Reactivity](https://docs.solidjs.com/concepts/reactivity) · [Avoid unnecessary effects](https://docs.solidjs.com/guides/avoid-unnecessary-effects)
- For asynchronous reads, return the promise from a memo or derived store and read it under `Loading` and `Errored` as appropriate. Solid discards superseded results. Request cancellation, where needed, is a separate concern. Keep setters out of component bodies and tracked computations. [Async reactivity](https://docs.solidjs.com/concepts/async-reactivity) · [Owned writes diagnostic](https://docs.solidjs.com/reference/solid-js/diagnostics/reactive-write-in-owned-scope)
- For an editable scalar seeded by reactive data, use `createSignal(() => props.value)`. Its setter establishes a local override; the next source recomputation can replace that override. For nested editable data, use `createStore(source, seed)` and write through the setter's draft. The source can mutate the draft or return data to reconcile. Use `createProjection` for read-only structured derivations and a plain signal or store for drafts whose lifetime is independent of upstream refreshes. Match the reset dependency to the intended behavior, especially when only a change of entity should discard edits. [createSignal](https://docs.solidjs.com/reference/solid-js/reactivity/create-signal) · [createStore](https://docs.solidjs.com/reference/solid-js/stores/create-store) · [Stores](https://docs.solidjs.com/concepts/stores)

## Keep interactions and mutations at their source

- Run interaction-specific work from the handler that caused it. Keep handlers stable and choose the branch or read the latest callback prop inside the handler. Pass the event's value directly to the next operation when it needs that value immediately. Solid queues setters, so an immediate accessor read typically sees the committed value from before the write. Functional setters compose pending updates. `flush()` applies synchronous work for assertions and imperative reads where appropriate. [Components and JSX](https://docs.solidjs.com/concepts/components-and-jsx) · [Reactivity](https://docs.solidjs.com/concepts/reactivity) · [Testing](https://docs.solidjs.com/guides/testing)
- Use `action` for a mutation whose writes need to share a transaction across asynchronous work. Ordinary writes are held until commit. Optimistic writes are visible during the action and revert to the underlying state when it settles, so reconcile the authoritative value on success. A yielded promise resumes in the transaction. In an async generator, resume with a bare `yield` after `await` before transaction-dependent reads, writes, or refreshes. Avoid `flush()` inside an action. A bare `refresh` is quiet, and `affects(source)` before refresh declares a change for pending indicators. [action](https://docs.solidjs.com/reference/solid-js/lifecycle-actions/action) · [Mutations](https://docs.solidjs.com/concepts/mutations) · [Async reactivity](https://docs.solidjs.com/concepts/async-reactivity)
- For imperative work that must follow a settled update, a handler can schedule `onSettled` for a single callback. Use `onFlush` from the handler when work must run after the pending flush even if an async transition is still held. Handler-scheduled callbacks have no owner-bound cleanup. [onSettled](https://docs.solidjs.com/reference/solid-js/lifecycle-actions/on-settled) · [onFlush](https://docs.solidjs.com/reference/solid-js/lifecycle-actions/on-flush)

## Tie setup to the DOM and owner lifetime

- A ref callback receives the created element before insertion. Capture the node there, or apply behavior that can run on a detached element. The callback is untracked and unowned, and its return value is ignored. Register lifecycle work in the component or in an owned directive factory that returns the ref callback. Use JSX handlers for ordinary element events. A listener requiring native options or an exact event name can be managed by the directive, with matching removal in its owner-bound teardown. [Refs and directives](https://docs.solidjs.com/concepts/components-and-jsx#refs-and-directives) · [ref](https://docs.solidjs.com/reference/solid-web/jsx-properties/ref)
- Register `onSettled` in the owner for one-time setup that requires mounted DOM, such as initial focus, a global listener, or an observer. It runs untracked after the owner settles, including pending async work. Return teardown from the callback. Reads there do not subscribe, and immediate reads after writes still see the pre-write value. Registering `onCleanup` within the callback or within a ref is forbidden. Low-level `onCleanup` belongs in an appropriate reactive owner. [onSettled](https://docs.solidjs.com/reference/solid-js/lifecycle-actions/on-settled) · [onCleanup](https://docs.solidjs.com/reference/solid-js/advanced/specialized-reactivity/on-cleanup)
- Place per-open setup in a child owned by a `Show` branch so closing disposes it and reopening sets it up again. A non-keyed branch stays mounted across truthy-to-truthy changes. Its function child receives an accessor that should be read in a tracking scope. Keyed `Show` remounts when the identity of `when` changes and supplies the raw value. Choose keyed behavior when disposal and recreation are part of the desired reset. CSS visibility preserves the owner. [Show](https://docs.solidjs.com/reference/solid-js/components-jsx/show)

## Feed subscriptions into the graph

- For a fixed browser-only listener or observer, subscribe in owned `onSettled`, write from the external callback, and unsubscribe in the returned cleanup. Browser observations such as measured size are new inputs. Register another owned lifetime or use a reactive subscription when the source needs to change while the component stays mounted. [External observations](https://docs.solidjs.com/guides/avoid-unnecessary-effects#let-external-observations-become-new-inputs)
- For an external push source that represents a value, return `from(source)` from a memo. It accepts a subscription function that returns an unsubscribe callback, an Observable, or an async iterable. Capture reactive source selection in the compute function. A new computation or its disposal closes the old source. Reads can suspend until the first value, and fast pushes may coalesce, so handle per-event commands at the event source. On SSR the subscription supplies its first value and closes, then subscribes again after hydration. Keep browser-only sources in a browser-only lifecycle or boundary. [from](https://docs.solidjs.com/reference/solid-js/reactivity/from) · [External integrations](https://docs.solidjs.com/guides/integrate-non-solid-code#feed-an-outside-source-into-the-graph)

## Keep effects at imperative boundaries

Use split `createEffect(compute, apply)` when settled reactive inputs must repeatedly drive a system outside Solid and JSX, a user event, or an owned setup callback cannot express that synchronization. Read every dependency in compute and pass the values into the untracked apply callback. Return cleanup from apply to release the previous binding before replacement and on disposal. Use `{ defer: true }` only if initial setup already has its own path or should be skipped. Apply runs when compute reruns even if its result compares equal. Put an equality-filtering memo upstream when repeated equivalent inputs should be suppressed. If an external API has separate construction and update operations, initialize and destroy it with owned `onSettled` and use the effect to send updates. [createEffect](https://docs.solidjs.com/reference/solid-js/reactivity/create-effect) · [External integrations](https://docs.solidjs.com/guides/integrate-non-solid-code)

## Preserve SSR and teardown behavior

Derived values used during rendering can execute on the server. Client effects and `onSettled` apply browser work after rendering, so moving code into a derivation changes its execution environment. Keep initial SSR and hydration output aligned. For browser-only modules that access globals at import time, use a dynamic import in `onSettled` or wrap the component in `clientOnly`. For async browser setup, return cleanup synchronously and guard the continuation so it cannot attach resources after disposal. For a replacement, verify the initial render, repeated interactions, source changes without remount, disposal and reopening, and the SSR/hydration path where applicable. [SSR-safe code](https://docs.solidjs.com/guides/ssr-safe-code) · [External integrations](https://docs.solidjs.com/guides/integrate-non-solid-code#keep-it-off-the-server) · [Testing](https://docs.solidjs.com/guides/testing)

## Retrocks call-site inventory

The audited working tree contains **48 production calls across 16 modules** and **4 calls in test harnesses**. The harness effects observe controller reactivity. Treat this count as a baseline for reporting. Refresh it before implementation because Pointing Poker and Board work may change it.

### Board and shared UI

- **BoardWorkspace (11).** Move the rename input binding to its mounted editor and evaluate close-time focus separately. Use the Add Column dialog's existing initial focus if it covers pointer, keyboard, and touch. Derive the same-Board mode announcements from current and previous state. Run the development colophon when a real Board first mounts, including soft-navigation loads. Scope search, quick filter, sort, selected Column, and mobile drafts to Board identity. Preserve same-Board drafts across live snapshots and Co-Facilitator claims. For a missing Board, preserve overlay teardown, rename and composer cancellation, error reset, and the heading focus transition. Locking cancels rename and Add Column even when the lock arrives remotely. A deleted or redacted Card must clear the selected Card Detail and stay closed if the Card returns. Recent Boards is reactive storage synchronization. The mobile Column rail scroll follows selection from click, swipe, shortcuts or agent actions and changes to the Column roster.
- **ColumnPanel (4).** Candidate replacements are conditional rename-input binding and mounted composer registration with cleanup. Keep the close-time title focus fallback, the cancellation of editing and menus on lock, and correct shortcut targets across Column reorder, removal, and remount.
- **CardItem (4).** Move editor input binding to mount. Preserve focus fallback to Card actions, cancellation on live lock, and cancellation on redaction. The redaction effect also resets error and whisper state and cleans up a timer. A redacted-only owner can take over the timer if it covers the same disposal and re-entry cases.
- **CardGroupItem (3).** Move editor input binding to mount. Handle failed move focus at the mutation outcome once the trigger is enabled again, with scroll preserved. Verify the separate close-time title focus fallback across Escape, blur, save, and live changes.
- **CardReactions (1).** Derive or scope the picker open state to the enabled lifetime. A remotely disabled picker closes and remains closed when enabled again.
- **BoardVotingSettings (1).** Evaluate an open-session draft seeded once per opening, with its original settings as the patch baseline. Check controlled opening, live updates while the drawer is open, save failures, nested confirmation, and exit animation before replacing the effect.
- **ActionItemsDrawer (2) and CardDetailDrawer (2).** Evaluate declarative input value binding using the current Action Item owner while idle and the editor's draft while active. Preserve no-op and trimmed saves, failed draft and retry, Escape layering, and live updates. Evaluate focus and state reset using the controlled overlay lifecycle. Action Items resets filter and copy status on opening and restores focus to the original control or More. Card Detail restores focus on explicit close and has a separate abrupt-unmount fallback when focus is on the body. Preserve animation and avoid restoring focus twice or stealing it from a new target.
- **CountdownTimer (4).** The 100 ms monotonic ticker and visibility listener follow the running lifetime. An owned ticker can replace the effect if cleanup, restart, and clock behavior match. The expiry effect tracks whether the current deadline was observed running and issues one mute-aware chime on expiry. Keep that imperative boundary until an equivalent transition can observe clock and remote changes without replaying expired snapshots. The configuration announcement is a candidate for a pure previous/current derivation. Preserve its initial empty text, unchanged-snapshot behavior, and consecutive extension announcements. Check whether the popover's existing content initial focus covers the explicit focus effect for both pointer and the Facilitator shortcut.
- **FacilitatorLinkClaim (1).** Key the loading attempt and hash listener to Board identity. A keyed owned child is viable only if it preserves initial and later hash claims, latest-attempt and pathname checks, cleanup and URL-fragment scrubbing. The effect is a valid boundary for this subscription and its asynchronous work.

### Pointing Poker

- **PokerWorkspace (2).** Move Room name input binding to editor mount and evaluate close-time heading focus separately. Preserve selection on entry and restore focus only when the body owns it.
- **PokerStoryTitleEditor (4).** Move input binding to mount and evaluate close-time restoration, including the queue Pencil fallback and stage heading. The other two effects cancel edits and reset error and tap state when the Story changes or editing permission is lost. A keyed edit session or unified invalidation can replace them only if the draft stays discarded when permission returns and save/confirmation results cannot act on the wrong Story.
- **PokerStoryQueue (2).** An active confirmation owner can manage capture listeners, registration, Cancel focus, and cleanup. Verify that registration precedes focus, that outside pointer or focus dismisses without stealing focus, and that Cancel and Escape restore the reinserted Delete button. Test live lock, removal, and late votes that change the discard warning and round identity.
- **Joined Room route (1).** Recent Rooms persists reactive Room name and visit state. Keep the storage boundary unless a replacement covers the initial join, optimistic rename and rollback, authoritative rename, and visit timing.

### Controllers and live transport

- **Board controller (4).** Route ingress reconciles snapshots into the authoritative state shared with HTTP actions and live updates. The stream follows live Board identity and availability, and a separate reconnect effect reopens the session after a successful Co-Facilitator claim. These responsibilities can stay as effects. Live signal ingestion could move to the transport callback if the migration preserves callback timing, committed state, event ordering and burst handling, revision gaps and recovery, clock and presence, stale-source rejection, and terminal disposal. Preserve the existing adapter and transport interfaces.
- **Pointing Poker controller (2).** Keep route snapshot reconciliation and the live stream lifecycle unless an equivalent preserves ID and version ordering, optimistic state, joined and closed state, presence, and connection teardown. A route snapshot plus latest-event memo cannot recover a newer authoritative snapshot once its source is overwritten.

The existing Board and Poker component suites are the main behavior seams. Use controller tests for injected snapshot, mutation, and live-transport events, and the App suite for navigation and Room lifecycle. The repository has client jsdom and server Vitest projects. Browser checks during implementation should cover hydration, mounted focus, and mobile Column rail scrolling where jsdom cannot establish parity. These are verification targets for the refactor. This audit did not execute the application suite.
